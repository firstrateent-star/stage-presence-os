# Chat Workflow Transition

## Decision
The current chat-first operating workflow is a temporary validation bridge, not the permanent architecture for Stage Presence OS or Vlourish.

For now:

**real business input -> ChatGPT interpretation -> Stage Presence OS update**

This intentionally keeps cost and infrastructure low while real Stage Presence work teaches us what the native system actually needs.

## Long-term target
As Stage Presence and Vlourish scale, and more capital is available for hosting, storage, compute, AI/API usage and integrations, the interpretation and intake work currently performed through ChatGPT should progressively move into Stage Presence OS itself.

The desired mature path is:

**real business input -> native secure Stage Presence capture -> original source retained -> interpretation/matching -> canonical business truth or review candidate -> human only for material exceptions**

Likely native inputs eventually include photographed lead sheets, typed natural-language capture, voice, authorized email/message intake, website inquiries, documents/contracts, spreadsheets/imports, commercial/payment evidence and operational updates.

## Governing principle
Do not preserve the current chat-first workflow merely because it works. Its purpose is to validate the business model and interpreter behavior before spending more capital or automating the wrong process.

Native integration should be earned when real use shows enough volume, repeated transfer friction, source-retention need, multi-user need, or economic justification to support the required hosting/storage/AI/integration costs.

Until then, chat-first remains a low-cost learning bridge. The backend must continue to be designed so this bridge can later be removed without rebuilding the canonical Stage Presence model.
