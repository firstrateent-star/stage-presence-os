# Human Interface v2

Stage Presence frontend is not a visual mirror of the backend.

The backend may remain deep, normalized, evidence-aware, and domain-rich. The human surface exists to reduce cognitive burden and support decisions, actions, understanding, and orientation.

## Governing principles

1. **A backend domain does not earn a frontend destination merely by existing.**
2. **A frontend element earns visibility only when it supports a human decision, action, understanding, or orientation.**
3. **Role changes attention, not truth.** The same canonical backend supports different human lenses.
4. **System language stays precise in the backend; human language may be simpler in the interface.**
5. **Progressive disclosure beats page proliferation.** Deep detail should appear when the person asks for it or when the situation makes it relevant.
6. **Capture is the universal front door for new reality.** Humans should not have to choose a backend table or semantic category before telling the system what happened.
7. **Observability is a system concern.** Recovery, Reality Health, AI evaluation, and governance belong under System unless a specific issue becomes operationally relevant.

## Primary operating shell

The everyday shell is intentionally small:

- **Today** — What needs me now?
- **Work** — What is moving?
- **Capture** — What happened?
- **Explore** — What do I want to understand more deeply?

Admin/system observability sits under **System**.

Relationships, Capability, and Economy remain important backend domains but no longer compete equally for permanent daily navigation. They are reached through Explore or contextual links.

## Work story

Opening work should answer, in this order:

1. **Who**
2. **When + where**
3. **What they need**
4. **What we promised**
5. **What is ready**
6. **What is not**
7. **What is next**

Then progressively disclose:

- Manage what happens next
- People, timeline + delivery
- Money
- What actually happened?
- What should we remember?

The underlying canonical commands remain unchanged.

## Vocabulary translation

Backend precision remains authoritative. Human-facing labels may translate it:

| Backend | Human surface |
| --- | --- |
| Engagement | Work / Event / Project |
| commitment_state SIGNED | Confirmed |
| resource_commitment | Reserved / committed capacity |
| engagement_assignment | Crew |
| engagement_schedule_item | Timeline |
| engagement_facts | What we know / Need to know |
| UNKNOWN | Need to know |
| engagement_cost_items | Job costs |
| relationship_summary | Customer / partner history |
| capability_summary | What we can deliver |
| recovery_queue | System issue / missing reality |

## Vlourish interpretation

Backend petals converge toward the person. The person should not navigate the petals themselves.

The desired flow is:

**deep backend → selective contract → role-aware attention → human action → new reality**

Frontend v2 should therefore be judged less by feature count and more by whether the right person can understand what matters and act without learning the system's internal ontology.
