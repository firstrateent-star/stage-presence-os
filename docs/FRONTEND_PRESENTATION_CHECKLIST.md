# Frontend Presentation Checklist

Use this whenever a backend field, table, view or derived signal is proposed for display.

1. **User / moment** — Who needs this, and at what point in the Engagement lifecycle?
2. **Tier** — Is it ATTENTION, SUMMARY, OPERATING_DETAIL, REFERENCE or EVIDENCE?
3. **Decision leverage** — What decision, action or understanding improves because it is visible?
4. **Placement** — Today, Work, Engagement, Contributor, Client, Playbook or Evidence?
5. **Compression** — Can several raw facts be represented by one human-readable state, metric or sentence?
6. **Progressive disclosure** — Does it belong on the default surface, or behind a section/disclosure/search?
7. **Semantics** — Are unknown, zero, not represented, suggested, committed and approved clearly distinct?
8. **Presenter** — Is the field mapped through a presentation model rather than parsed ad hoc in the screen?
9. **Visual budget** — What existing information should remain hidden/collapsed so the screen does not become denser by default?
10. **Contract safety** — Is the backend read contract additive, or does a semantic change require a new version?

Default answer for a new backend field is **do not display it yet**.

Canonical rule: **Store richly. Interpret centrally. Present selectively. Reveal progressively.**
