# Contextual Capture v0.1

## Center

**The easiest way to improve Stage Presence reality is to let people report what changed from the context they are already working in.**

Contextual Capture embeds the existing governed Capture Intelligence runtime directly inside an Engagement's business story.

## Why

The global Capture surface remains useful for:

- creating a new opportunity;
- manually routing a fact;
- manually routing an unknown;
- manually setting a next move;
- capturing a source photo.

But ordinary operating updates already have an Engagement context. Requiring the user to leave that Engagement, open global Capture, switch to Existing Work, and re-select the same Engagement creates avoidable friction.

Contextual Capture removes only that friction. It does not create a new truth path.

## Runtime

`Engagement context -> natural-language update -> Capture Intelligence -> explicit review -> governed canonical commands / tracked Unknowns -> review trace`

The same interpreter, authority model, source preservation, Unknown routing, and review trace are reused.

## Boundaries

Contextual Capture does not:

- auto-approve proposals;
- infer payments as verified;
- create a second Engagement update store;
- bypass canonical assignment, schedule, or resource-commitment commands;
- turn an unrecognized sentence into structured truth;
- replace manual structured Capture.

## Evidence goal

At introduction, live Stage Presence had zero persisted Capture review traces. Contextual Capture is therefore an adoption intervention: make the governed runtime easier to use in normal work, then observe whether real review evidence begins to accumulate.

Its value should eventually be judged by evidence such as:

- Capture review traces appearing in ordinary operation;
- reduced manual navigation/data-entry friction;
- higher-quality schedule, crew, capacity, fact, and Unknown evidence;
- human rejection/correction patterns that improve future evals.

Implementation alone does not prove value.
