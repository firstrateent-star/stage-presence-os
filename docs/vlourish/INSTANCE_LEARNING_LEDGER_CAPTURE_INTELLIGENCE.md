# Stage Presence Instance Learning Ledger — Capture Intelligence

Status: **INSTANCE LEARNING / NOT VLOURISH CANON**

## Observation: intelligence should propose commands, not own truth

Stage Presence already contains deterministic canonical homes for Schedule, Assignments, Resource Commitments and collection evidence. The first Capture Intelligence implementation therefore inserts an interpretation/review boundary above those commands rather than creating an AI-owned truth store.

### Candidate learning

When canonical command boundaries already exist, intelligent intake may create more value by producing governed proposals than by writing domain records directly.

Cross-validation required before promotion.

---

## Observation: actual correction cases are better eval seeds than generic NLP benchmarks

Existing Stage Presence recovery work already exposed important semantic errors:

- Goodshuffle `Sales Lead` must not imply field crew.
- represented Resource scope must not imply reservation or actual use.
- reported collection must not imply externally verified collection.
- a clock time must not cause the system to invent a missing date.

These became the first executable Capture evals.

### Candidate learning

Instance corrections can form a high-value golden eval set because they measure the errors that would actually damage the system's model of reality.

Cross-validation required before promotion.

---

## Observation: source preservation precedes interpretation

Capture v0.1 preserves the original source before approved proposals are applied and links the source artifact to resulting operating records where supported.

### Candidate learning

In evidence-sensitive systems, interpretation should be reconstructable from preserved source rather than replacing it.

Already consistent with the current Vlourish architecture; continue collecting instance evidence.

---

## Observation: Unknown is a routed outcome, not parser failure

Capture may successfully detect a reported payment while leaving amount or accounting verification unknown. The runtime treats that as a valid interpretation rather than fabricating a complete transaction.

### Candidate learning

A useful intelligence system should be evaluated partly on its ability to preserve decision-relevant unknowns, not only on extraction completeness.

Cross-validation required before promotion.
