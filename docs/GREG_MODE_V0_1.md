# Greg Mode v0.1

Greg Mode is the first role-specific Stage Presence interface governed by the Vlourish principle:

> The backend models the business. The frontend models the human's relationship to the business.

## Purpose

Greg should not operate the Stage Presence data model. He should receive compressed owner-level attention:

- decisions and exceptions that may need owner judgment;
- high-value/current relationships worth attention;
- upcoming work where risk or leverage makes an owner glance useful;
- a small evidence-backed business pulse;
- universal Capture.

## What Greg Mode does not claim

Stage Presence does not yet have a canonical `decision_owner = Greg` contract. Therefore Greg Mode does **not** label surfaced items as assigned to Greg.

It labels them as **owner-attention candidates** derived from existing evidence. This is an attention lens, not authority or assignment truth.

The first pilot maps the existing `ADMIN` role to Greg Mode because the live instance currently has one active ADMIN membership. This is a transitional product choice, not a claim that every future ADMIN is Greg.

## Primary owner surface

Greg's Today view contains:

1. **Needs You**
   - high-leverage Recovery candidates in economics, demand, relationship, capacity, pricing, and commercial domains;
   - blocked/attention-heavy Engagements;
   - materially high-value active work where an owner glance may be useful.

2. **Relationships**
   - recurring/current relationships prioritized by current/future work and represented committed value;
   - never presented as a generic contact directory.

3. **Coming Up**
   - committed upcoming work only when represented risk/value crosses the owner-attention threshold;
   - not every Stage Presence job.

4. **Business Pulse**
   - open pipeline;
   - committed revenue;
   - collected value;
   - contribution only where actual contribution evidence exists.

5. **Capture**
   - universal reality intake remains available from the owner shell.

## Navigation

For the owner pilot, primary navigation is reduced to:

- Today
- Capture

`All work` and `System` remain available as secondary/reference paths. Relationships, Capability, Economy, Recovery, and other backend/system concepts do not compete for Greg's primary attention.

## Evidence rules

Greg Mode must never:

- infer Greg is assigned to a decision merely because it matters;
- infer customer outreach is required without evidence;
- turn missing structured evidence into a negative business claim;
- label approval/review behavior as model accuracy;
- calculate unsupported contribution or profitability;
- expose backend domains simply because they exist.

## Future evolution

The correct long-term contract is likely explicit decision/action ownership:

`Reality -> signal -> action/decision needed -> owner -> minimum context -> human surface`

Once the backend earns that contract, Greg Mode should replace heuristic owner-attention selection with canonical ownership while retaining the same low-cognition interface.
